# RBAC Data Model

## Database Schema

The following tables will be added to support the Role-Based Access Control system:

### 1. `permissions` Table

Defines the individual permissions available in the system.

```sql
CREATE TABLE `permissions` (
  `id` char(36) NOT NULL,
  `name` varchar(50) NOT NULL,
  `description` text,
  `module` varchar(50) NOT NULL,
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_permissions_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

**Fields:**
- `id`: Unique identifier (UUID)
- `name`: Permission identifier (e.g., 'products.view')
- `description`: Human-readable description
- `module`: Functional area (e.g., 'inventory', 'sales')
- `created_at` / `updated_at`: Timestamps

### 2. `roles` Table

Defines roles that can be assigned to users.

```sql
CREATE TABLE `roles` (
  `id` char(36) NOT NULL,
  `tenant_id` char(36) NOT NULL,
  `name` varchar(50) NOT NULL,
  `description` text,
  `is_system_role` tinyint(1) NOT NULL DEFAULT '0',
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_roles_tenant` (`tenant_id`),
  CONSTRAINT `fk_roles_tenant` FOREIGN KEY (`tenant_id`) REFERENCES `tenants` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

**Fields:**
- `id`: Unique identifier (UUID)
- `tenant_id`: Associated tenant
- `name`: Role name (e.g., 'Admin', 'Store Manager')
- `description`: Human-readable description
- `is_system_role`: Flag for built-in roles that cannot be deleted
- `created_at` / `updated_at`: Timestamps

### 3. `role_permissions` Table

Maps permissions to roles (many-to-many relationship).

```sql
CREATE TABLE `role_permissions` (
  `id` char(36) NOT NULL,
  `role_id` char(36) NOT NULL,
  `permission_id` char(36) NOT NULL,
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_role_permission` (`role_id`,`permission_id`),
  KEY `idx_role_permissions_permission` (`permission_id`),
  CONSTRAINT `fk_role_permissions_permission` FOREIGN KEY (`permission_id`) REFERENCES `permissions` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_role_permissions_role` FOREIGN KEY (`role_id`) REFERENCES `roles` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

**Fields:**
- `id`: Unique identifier (UUID)
- `role_id`: Reference to roles table
- `permission_id`: Reference to permissions table
- `created_at`: Timestamp

### 4. `user_roles` Table

Associates users with roles in specific scopes.

```sql
CREATE TABLE `user_roles` (
  `id` char(36) NOT NULL,
  `user_id` char(36) NOT NULL,
  `role_id` char(36) NOT NULL,
  `scope` enum('tenant','store') NOT NULL DEFAULT 'tenant',
  `scope_id` char(36) DEFAULT NULL,
  `created_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` timestamp NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_user_roles_user` (`user_id`),
  KEY `idx_user_roles_role` (`role_id`),
  KEY `idx_user_roles_scope` (`scope`,`scope_id`),
  CONSTRAINT `fk_user_roles_role` FOREIGN KEY (`role_id`) REFERENCES `roles` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_user_roles_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_ai_ci;
```

**Fields:**
- `id`: Unique identifier (UUID)
- `user_id`: Reference to users table
- `role_id`: Reference to roles table
- `scope`: Scope type ('tenant' or 'store')
- `scope_id`: ID of the scope entity (tenant_id or store_id)
- `created_at` / `updated_at`: Timestamps

### 5. Changes to `users` Table

The existing `users` table will be modified to remove the deprecated fields:

```sql
ALTER TABLE `users` 
  DROP COLUMN `role`,
  DROP COLUMN `store_id`;
```

## Default Data

### Default Permissions

#### Inventory Module
- products.view
- products.create
- products.edit
- products.delete
- inventory.view
- inventory.adjust
- inventory.transfer

#### Sales Module
- pos.access
- sales.create

- sales.refund
- sales.discount
- sales.view

#### Customers Module
- customers.view
- customers.create
- customers.edit
- customers.delete

#### Reports Module
- reports.sales
- reports.inventory
- reports.financial
- reports.employee

#### Settings Module
- settings.view
- settings.edit
- settings.taxes
- settings.stores

#### Users Module
- users.view
- users.create
- users.edit
- users.delete
- roles.manage

### Default Roles

Three system roles will be created for each tenant:

1. **Admin**:
   - Has all available permissions at the tenant level
   - Can manage all stores, users, and settings

2. **Store Manager**:
   - Has most operational permissions at the store level
   - Cannot modify system settings or manage users/roles

3. **Cashier**:
   - Has limited permissions focused on daily operations
   - Can process sales, view products, and manage basic customer interactions

## Migration Strategy

The migration from the current simple role system to the new RBAC system will require careful planning:

1. **Create New Schema**: Add all new tables while keeping existing tables intact

2. **Seed Core Data**: Populate permissions and default roles

3. **Data Migration**: For each existing user, create appropriate entries in user_roles:
   ```sql
   INSERT INTO user_roles (id, user_id, role_id, scope, scope_id)
   SELECT 
       uuid_v4(),
       u.id,
       (SELECT r.id FROM roles r WHERE r.tenant_id = u.tenant_id AND r.name = 
           CASE 
               WHEN u.role = 'admin' THEN 'Admin'
               WHEN u.role = 'manager' THEN 'Store Manager'
               WHEN u.role = 'cashier' THEN 'Cashier'
           END
       ),
       CASE WHEN u.store_id IS NOT NULL THEN 'store' ELSE 'tenant' END,
       u.store_id
   FROM users u;
   ```

4. **Verification**: Ensure all users have appropriate role assignments

5. **Schema Cleanup**: Remove legacy columns from the users table only after the new system is fully operational and verified
