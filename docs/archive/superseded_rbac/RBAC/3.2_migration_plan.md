# RBAC Migration Plan

## Overview

This document outlines the strategy and implementation plan for migrating from the legacy role-based authorization system (using the `role` column in the `users` table) to the new Role-Based Access Control (RBAC) system using the `user_roles`, `roles`, and related tables.

## Current State

### Legacy Role System
- Simple role enumeration in `users` table: `role ENUM('admin','manager','cashier')`
- Direct `store_id` reference in `users` table
- Limited flexibility: one user can have only one role
- Limited scope: store assignment is at the user level, not role level

### New RBAC System
- Flexible role assignments through `user_roles` table
- Multiple roles per user
- Role assignments can be scoped to tenant-level or store-level
- Granular permissions associated with roles
- Support for role hierarchy and inheritance

## Migration Goals

1. **Simplify architecture**: Use a single source of truth for roles and permissions
2. **Increase flexibility**: Support multiple roles per user with different scopes
3. **Improve maintainability**: Eliminate redundant code managing two parallel systems
4. **Enable scalability**: Support more complex permission schemes as the application grows

## Migration Steps

### Phase 1: Data Migration and Integrity

#### 1.1 Create Data Migration Script
Create and run a migration script to ensure all users have appropriate RBAC roles based on their legacy role:

```sql
-- Step 1: Ensure all legacy roles exist in the 'roles' table for each tenant
INSERT IGNORE INTO roles (id, name, tenant_id, description, created_at, updated_at)
SELECT 
    UUID() as id,
    u.role as name,
    u.tenant_id,
    CONCAT('Migrated from legacy role system: ', u.role) as description,
    NOW() as created_at,
    NOW() as updated_at
FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM roles r 
    WHERE r.name = u.role AND r.tenant_id = u.tenant_id
)
GROUP BY u.role, u.tenant_id;

-- Step 2: Ensure all users have at least one role assignment in user_roles
INSERT INTO user_roles (id, user_id, role_id, scope, store_id, created_at, updated_at)
SELECT 
    UUID() as id,
    u.id as user_id,
    (SELECT id FROM roles WHERE name = u.role AND tenant_id = u.tenant_id LIMIT 1) as role_id,
    CASE WHEN u.store_id IS NULL THEN 'tenant' ELSE 'store' END as scope,
    u.store_id,
    NOW() as created_at,
    NOW() as updated_at
FROM users u
WHERE NOT EXISTS (
    SELECT 1 FROM user_roles ur WHERE ur.user_id = u.id
);
```

#### 1.2 Verify Data Integrity

### Phase 2: Authentication & Authorization Updates

#### 2.1 Update JWT Token Generation
Update the authentication service to use RBAC roles instead of the legacy role:

File: `/backend/services/authService.js`

```javascript
// Before:
const generateToken = (user) => {
  return jwt.sign({
    id: user.id,
    name: user.name,
    email: user.email,
    role: user.role,
    tenant_id: user.tenant_id,
    store_id: user.store_id,
    // other fields...
  }, JWT_SECRET, { expiresIn: '1d' });
};

// After:
const generateToken = async (user) => {
  // Get user's roles and permissions
  const userRoleService = require('./userRoleService');
  const roleInfo = await userRoleService.getUserRolesAndPermissions(user.id);
  
  return jwt.sign({
    id: user.id,
    name: user.name,
    email: user.email,
    tenant_id: user.tenant_id,
    store_id: user.store_id,
    // RBAC fields:
    systemRoles: roleInfo.roles.map(r => r.name),
    permissions: roleInfo.permissions,
    // other fields...
  }, JWT_SECRET, { expiresIn: '1d' });
};
```

#### 2.2 Update Authorization Middleware
Update the permission middleware to rely only on RBAC:

File: `/backend/middleware/authMiddleware.js`

```javascript
// Before:
const hasPermission = (requiredPermissions) => {
  return (req, res, next) => {
    // Legacy role-based access
    if (req.user.role === 'admin') {
      return next();
    }
    
    // Check RBAC permissions
    const userPermissions = req.user.permissions || [];
    const hasRequired = requiredPermissions.some(p => userPermissions.includes(p));
    
    if (hasRequired) {
      return next();
    }
    
    return res.status(403).json({ msg: 'Permission denied' });
  };
};

// After:
const hasPermission = (requiredPermissions) => {
  return (req, res, next) => {
    const userPermissions = req.user.permissions || [];
    const hasRequired = requiredPermissions.some(p => userPermissions.includes(p));
    
    if (hasRequired) {
      return next();
    }
    
    return res.status(403).json({ msg: 'Permission denied' });
  };
};
```

### Phase 3: User Management Updates

#### 3.1 Update User Creation
Modify user creation flow to use RBAC role assignments:

File: `/backend/routes/userRoutes.js`

```javascript
// Before:
router.post('/', [authenticate, hasPermission([PERMISSIONS.USER_CREATE])], async (req, res) => {
  const { name, email, password, role, store_id } = req.body;
  // ...
  const newUser = {
    id: uuid(),
    name,
    email,
    password_hash: hashedPassword,
    role,
    store_id: store_id || null,
    // other fields...
  };
  
  await connection.query('INSERT INTO users SET ?', [newUser]);
  // ...
});

// After:
router.post('/', [authenticate, hasPermission([PERMISSIONS.USER_CREATE])], async (req, res) => {
  const { name, email, password, roles, store_id } = req.body;
  // ...
  const newUser = {
    id: uuid(),
    name,
    email,
    password_hash: hashedPassword,
    // role field removed
    store_id: store_id || null,
    // other fields...
  };
  
  await connection.query('INSERT INTO users SET ?', [newUser]);
  
  // Assign roles via RBAC system
  if (roles && Array.isArray(roles)) {
    for (const role of roles) {
      await userRoleService.assignTenantRole(
        newUser.id,
        role.id,
        req.user.tenant_id,
        role.scope || 'tenant',
        role.store_id,
        req.user.id // assigned_by
      );
    }
  }
  // ...
});
```

#### 3.2 Update User Queries
Update queries that filter users by role:

```javascript
// Before:
const [managers] = await connection.query(
  'SELECT * FROM users WHERE role = ? AND tenant_id = ?',
  ['manager', tenantId]
);

// After:
const [managers] = await connection.query(`
  SELECT DISTINCT u.* 
  FROM users u
  JOIN user_roles ur ON u.id = ur.user_id
  JOIN roles r ON ur.role_id = r.id
  WHERE r.name = ? AND u.tenant_id = ?
`, ['manager', tenantId]);
```

exports.up = async function(db) {

  `);

## Rollback Plan

In case issues arise during the migration:

1. **Data Availability**: Keep a backup of the users table with the role column before removal
2. **Code Rollback**: Keep legacy role-based code in comments for quick restoration
3. **Parallel Operation**: Consider a period where both systems operate in parallel before full cutover

## Monitoring and Validation

After the migration:

1. Monitor authentication failures and permission denials
2. Validate user roles in the database match expected assignments
3. Check for any performance degradation in authorization checks
