# RBAC Service Consolidation Plan

## Overview

To create a more cohesive and maintainable RBAC system, we're consolidating the previously separate services (`userRbacService.js` and `userRoleService.js`) into a single unified `rbacService.js`. This document outlines our consolidation strategy and migration plan.

## Current Status

We have created a new consolidated `rbacService.js` that combines:

1. **Role assignment functions** (from userRoleService.js)
   - assignSystemRole
   - removeSystemRole
   - assignTenantRole
   - removeTenantRole

2. **Role retrieval functions** (from userRoleService.js)
   - getUserSystemRoles
   - getUserTenantRoles

3. **Permission functions** (from userRbacService.js)
   - getUserRolesAndPermissions
   - getUserPermissions
   - hasPermission
   - isTenantAdmin

## Service Updates Completed

The following key files have already been updated to use the new consolidated `rbacService.js`:

1. **Authentication Middleware** (`unifiedAuthMiddleware.js`)
   - Now uses `rbacService.getUserRolesAndPermissions()` for user authentication
   - Includes RBAC roles and permissions in JWT tokens

2. **RBAC Permission Middleware** (`rbacPermissionMiddleware.js`)
   - Updated to use `rbacService.getUserRolesAndPermissions()` and `rbacService.isTenantAdmin()`
   - Removed duplicate `isTenantAdmin` function from middleware

## Migration Plan

### Phase 1: Update Remaining APIs (July 1-5, 2025)
- Update all API route files to use the new `rbacService` instead of `userRbacService` or `userRoleService`
- Priority given to user management, tenant management, and store management routes
- Update any frontend services that directly use these services

### Phase 2: Add Missing Functions (July 6-10, 2025)
- Identify and migrate any unique functions from `userRoleService.js` that are not yet in `rbacService.js` 
- Ensure full backward compatibility with both original services

### Phase 3: Deprecate Old Services (July 11-15, 2025)
- Create proxy implementations in both original service files that:
  - Import the new `rbacService`
  - Export the same functions but delegate to `rbacService`
  - Log deprecation warnings when used
- Add deprecation comments in codebase with migration guidance

### Phase 4: Complete Removal (July 16-20, 2025)
- Once all code is using the new service directly, remove the old service files
- Verify all functionality still works properly
- Update documentation to reflect the new service structure

## Implementation Guidelines

1. **Backward Compatibility**
   - Maintain the same function signatures and return values
   - Ensure all edge cases are handled the same way

2. **Performance Optimizations**
   - Optimize database queries to reduce redundant calls
   - Cache frequently used data where appropriate
   - Add batch operations for multi-user management

3. **Testing Requirements**
   - Write unit tests for each function in the consolidated service
   - Add integration tests for key interactions with middleware
   - Test edge cases and error handling

## Validation Checklist

- [ ] All functions from original services are available in `rbacService.js`
- [ ] JWT token generation and validation works correctly
- [ ] Permission checking works for all routes
- [ ] Tenant admin bypass functionality works correctly
- [ ] User role assignment and removal works properly
- [ ] Store-specific permissions work correctly
- [ ] Development mode bypass still functions

## Rollback Plan

If any issues arise during the migration:

1. Revert the specific component causing issues to use the original service
2. Fix the issue in the consolidated service
3. Re-apply the update with proper testing

## Future Considerations

Once the service consolidation is complete, we can further enhance the RBAC system:

1. Add role inheritance capabilities
2. Implement permission grouping for more intuitive management
3. Create admin UI components for visualizing and editing permission structures
4. Add auditing for permission changes and authorization events
