# Current RBAC Implementation

## Overview

This document outlines the current state of authorization in our application, including both the legacy role system and the newer Role-Based Access Control (RBAC) implementation.

## Database Schema

### Legacy Role System
The legacy system uses a simple role enumeration in the `users` table:

```sql
CREATE TABLE users (
  id CHAR(36) NOT NULL PRIMARY KEY,
  tenant_id CHAR(36) NOT NULL,
  name VARCHAR(255) NOT NULL,
  email VARCHAR(255) NOT NULL,
  phone_number VARCHAR(30),
  password_hash VARCHAR(255) NOT NULL,
  role ENUM('admin', 'manager', 'cashier') NOT NULL,
  profile_picture_url VARCHAR(255),
  store_id CHAR(36),
  is_active TINYINT(1) DEFAULT 1,
  last_login_at DATETIME,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (tenant_id) REFERENCES tenants(id),
  FOREIGN KEY (store_id) REFERENCES stores(id)
);
```

### New RBAC System
The new RBAC system uses multiple tables to manage roles and permissions:

```sql
CREATE TABLE roles (
  id CHAR(36) NOT NULL PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  tenant_id CHAR(36) NOT NULL,
  description VARCHAR(255),
  is_system_role BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (tenant_id) REFERENCES tenants(id)
);

CREATE TABLE permissions (
  id CHAR(36) NOT NULL PRIMARY KEY,
  name VARCHAR(50) NOT NULL,
  description VARCHAR(255),
  category VARCHAR(50),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE role_permissions (
  id CHAR(36) NOT NULL PRIMARY KEY DEFAULT (UUID()),
  role_id CHAR(36) NOT NULL,
  permission_id CHAR(36) NOT NULL,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (role_id) REFERENCES roles(id),
  FOREIGN KEY (permission_id) REFERENCES permissions(id),
  UNIQUE KEY (role_id, permission_id)
);

CREATE TABLE user_roles (
  id CHAR(36) NOT NULL PRIMARY KEY DEFAULT (UUID()),
  user_id CHAR(36) NOT NULL,
  role_id CHAR(36) NOT NULL,
  store_id CHAR(36),
  scope ENUM('tenant', 'store') NOT NULL DEFAULT 'tenant',
  assigned_by CHAR(36),
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (role_id) REFERENCES roles(id),
  FOREIGN KEY (store_id) REFERENCES stores(id)
);
```

## Current Authorization Flow

### Authentication Process
1. User logs in with email/password
2. System validates credentials
3. JWT token is generated including:
   - Legacy role (`user.role`)
   - User's primary store (`user.store_id`)
   - RBAC permissions (`permissions` array)
   - System roles (`systemRoles` array)

### Permission Checking
Currently, the system uses a mix of both role-based checking:

```javascript
// Role-based check (legacy)
if (req.user.role === 'admin') {
  // Allow access
}

// Permission-based check (RBAC)
if (req.user.permissions.includes('user:update')) {
  // Allow access
}
```

### Key Services

#### User Role Service
Manages the assignment of roles to users:
- `assignTenantRole`: Assigns a role to a user with tenant or store scope
- `removeUserRole`: Removes a role from a user
- `getUserRoles`: Retrieves all roles for a user

#### Role Service
Manages roles and their permissions:
- `getTenantRoleById`: Gets a role by ID for a specific tenant
- `createRole`: Creates a new role
- `updateRole`: Updates an existing role
- `deleteRole`: Deletes a role
- `assignPermissionToRole`: Assigns a permission to a role

## Current Issues and Limitations

1. **Dual Systems**: Running both legacy and RBAC systems in parallel creates confusion
2. **Inconsistent Authorization**: Some parts of the code check the legacy role, others check RBAC permissions
3. **Store Management**: Store assignments happen at both the user level and role level
4. **Role Assignment Errors**: Failures when attempting to assign roles with null IDs
5. **JWT Token Redundancy**: Token contains redundant role information

## Current Default Roles

The system has three default roles that match the legacy roles:

1. **Admin**: Full system access
2. **Manager**: Store management and reporting
3. **Cashier**: Point of sale and basic customer operations
