# RBAC Troubleshooting Guide

## Current System Overview

The Zettaz Cloud application implements a two-tier RBAC (Role-Based Access Control) system with subscription management. The current implementation consists of:

1. **Authentication Middleware** - Verifies JWT tokens and extracts user information
2. **Permission Middleware** - Checks if authenticated users have required permissions
3. **Subscription Integration** - Verifies tenant subscription status and feature access

## Known Issues and Fixes

### 1. Authentication Middleware Issues

#### Issues:
- Inconsistent tenant ID extraction from JWT tokens (mix of snake_case and camelCase)
- Unreliable development mode fallback due to undefined NODE_ENV
- Verbose and duplicated code for token extraction and verification

#### Fixes:
- Standardize tenant and store ID extraction from tokens
- Force development mode in local environment when NODE_ENV is undefined
- Improve error handling and fallback mechanisms
- Reduce code duplication with helper functions

```javascript
// Improved token extraction
const tenantId = decoded.tenant_id || decoded.tenantId || null;
const storeId = decoded.store_id || decoded.storeId || null;

// Consistent user context object structure
req.user = {
  id: decoded.id,
  email: decoded.email,
  tenant_id: tenantId,
  tenantId: tenantId,  // Include both for backward compatibility
  store_id: storeId,
  storeId: storeId     // Include both for backward compatibility
};
```

### 2. Permission Middleware Issues

#### Issues:
- Complex permission checking logic spread across multiple files
- No proper tenant admin bypass for permission checks
- Missing or incomplete error handling for missing user ID or tenant ID
- Inefficient SQL queries for permission checking

#### Fixes:
- Implement tenant admin bypass to simplify permission checks for admins
- Standardize error handling for missing user or tenant IDs
- Optimize SQL queries with proper indices and simplified logic
- Add clear debug logging for troubleshooting permission issues

```javascript
// Tenant admin bypass example
const isTenantAdmin = await checkUserIsTenantAdmin(userId, tenantId);
if (isTenantAdmin) {
  return next(); // Skip permission check for tenant admins
}
```

### 3. Subscription Integration Issues

#### Issues:
- Incomplete feature verification based on subscription plans
- Missing subscription status checks in some routes
- No caching of subscription status leading to repeated database queries

#### Fixes:
- Implement proper subscription status verification
- Add feature-based access control tied to subscription plans
- Implement efficient caching for frequently accessed subscription data

## Debugging Tips

### Authentication Issues
- Check JWT token structure (should contain `id`, `tenant_id`, `store_id`)
- Verify JWT_SECRET environment variable is set correctly
- Look for "JWT decoded" log messages to see token content

### Permission Issues
- Check if user has proper role assignments in `user_roles` table
- Verify role has necessary permissions in `role_permissions` table
- Look for "PERMISSION MIDDLEWARE" log messages for detailed debugging

## Database Queries

### Check User's Tenant Roles
```sql
SELECT r.name, ur.scope, ur.store_id
FROM user_roles ur
JOIN roles r ON ur.role_id = r.id
WHERE ur.user_id = ? AND r.tenant_id = ?;
```

### Check User's Permissions
```sql
SELECT DISTINCT p.name
FROM permissions p
JOIN role_permissions rp ON p.id = rp.permission_id
JOIN user_roles ur ON rp.role_id = ur.role_id
JOIN roles r ON ur.role_id = r.id
WHERE ur.user_id = ? AND r.tenant_id = ?;
```
