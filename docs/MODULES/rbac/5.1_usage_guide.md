# RBAC and Subscription System Usage Guide

This guide demonstrates how to properly implement the Role-Based Access Control (RBAC) and Subscription systems in your API routes. The examples show best practices for combining authentication, permission checking, and subscription verification.

## Basic Route Protection

For basic tenant-level operations requiring simple permission checks:

```javascript
const { authenticate } = require('../middleware/auth');
const { hasPermission } = require('../middleware/permissionMiddleware'); 
const { PERMISSIONS } = require('../middleware/permissionMiddleware');

// Get users for a tenant (requires 'users.read' permission)
router.get('/api/users',
  authenticate,                         // Verify JWT token & extract user info
  hasPermission(PERMISSIONS.TENANT.USER.READ),  // Check if user has required permission
  userController.getUsers
);
```

## Store-Specific Operations

For operations that are specific to a store within a tenant:

```javascript
// Get inventory for a specific store (requires 'inventory.view' permission)
router.get('/api/stores/:storeId/inventory',
  authenticate,
  hasPermission(PERMISSIONS.TENANT.INVENTORY.VIEW),
  inventoryController.getStoreInventory
);
```

## Subscription-Based Feature Access

For features that should only be available to users with specific subscription plans:

```javascript
const { requireActiveSubscription, requireFeature } = require('../middleware/subscriptionMiddleware');

// Access advanced reporting feature (requires active subscription with 'advancedReporting' feature)
router.get('/api/reports/advanced',
  authenticate,
  requireActiveSubscription(),          // Check if tenant has active subscription
  requireFeature('advancedReporting'),  // Check if subscription includes this feature
  hasPermission(PERMISSIONS.TENANT.REPORTS.VIEW),
  reportController.getAdvancedReports
);
```

## Usage Limit Enforcement

For enforcing usage limits based on subscription plan:

```javascript
const { withinUsageLimits } = require('../middleware/subscriptionMiddleware');
const storeService = require('../services/storeService');

// Create a new store (checks if tenant is within store limit)
router.post('/api/stores',
  authenticate,
  hasPermission(PERMISSIONS.TENANT.STORES.CREATE),
  withinUsageLimits('stores', storeService.countStoresByTenant), 
  storeController.createStore
);
```

## Complex Route with Multiple Checks

For routes requiring multiple permission and subscription checks:

```javascript
// Import all necessary middleware
const { authenticate } = require('../middleware/auth');
const { hasPermission, PERMISSIONS } = require('../middleware/permissionMiddleware');
const { 
  requireActiveSubscription, 
  requireFeature, 
  withinUsageLimits 
} = require('../middleware/subscriptionMiddleware');
const userService = require('../services/userService');

// Create a new user with role assignment (complex checks)
router.post('/api/users',
  authenticate,
  requireActiveSubscription(),
  withinUsageLimits('users', userService.countUsersByTenant),
  hasPermission(PERMISSIONS.TENANT.USER.CREATE),
  async (req, res, next) => {
    // Additional middleware to check role-specific features
    if (req.body.role === 'advanced_user') {
      return requireFeature('advancedUserRoles')(req, res, next);
    }
    return next();
  },
  userController.createUser
);
```

## Admin-Only Operations

For operations that should only be accessible to tenant administrators:

```javascript
// Delete a user (admin-only operation)
router.delete('/api/users/:userId',
  authenticate,
  hasPermission(PERMISSIONS.TENANT.USER.DELETE, { skipAdminBypass: false }),
  userController.deleteUser
);
```

## System-Level Operations

For platform administrators managing the entire system:

```javascript
// Get all tenants (system admin only)
router.get('/api/system/tenants',
  authenticate,
  hasPermission(PERMISSIONS.SYSTEM.TENANTS.VIEW),
  systemController.getAllTenants
);
```

## Custom Permission Checking

If you need to check permissions manually in a controller:

```javascript
const { checkUserIsTenantAdmin } = require('../middleware/permissionMiddleware');
const permissionService = require('../services/permissionService');

async function customController(req, res) {
  const userId = req.user.id;
  const tenantId = req.user.tenant_id;
  
  // Check if user is tenant admin
  const isAdmin = await checkUserIsTenantAdmin(userId, tenantId);
  
  if (isAdmin) {
    // Admin-specific logic
  } else {
    // Check specific permission
    const hasSpecificPerm = await permissionService.hasPermission(
      userId, 'specific.permission', tenantId
    );
    
    if (!hasSpecificPerm) {
      return res.status(403).json({ message: 'Permission denied' });
    }
    
    // Permission-specific logic
  }
  
  // Rest of controller logic
}
```

## Best Practices

1. **Consistent Ordering**: Always place middleware in this order:
   - `authenticate`
   - `requireActiveSubscription` / subscription checks (if needed)
   - `hasPermission`

2. **Use Constants**: Always use the `PERMISSIONS` constants for permission names.

3. **Tenant Admin Bypass**: Remember that tenant admins bypass all tenant-level permission checks by default.

4. **Error Handling**: All middleware includes proper error handling, but add try/catch blocks in your controllers.

5. **Subscription Features**: Always check subscription status before checking specific features.

6. **Development Mode**: The system will automatically use headers for authentication in development mode.

## Troubleshooting

If you encounter permission issues:

1. Check if the user has the required role in `user_roles` table
2. Verify the role has the necessary permissions in `role_permissions`
3. Ensure the tenant ID is correctly extracted from the token
4. Look for "PERMISSION MIDDLEWARE" log entries for detailed debugging
5. Verify subscription status in the `subscriptions` table
